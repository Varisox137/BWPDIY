# 自动编号与描述标点避让设计

## 目标

1. 无 ID 的主要式神、卡牌和衍生物在保存或上传卡图时自动获得符合 BWPro 号段习惯的 ID，不再默认回退到卡名命名。
2. 项目可携带全库唯一的三位项目 ID，与默认异画位 `1` 和两位式神序号组成标准六位式神 ID。
3. 自动换行尽可能避免闭合标点位于行首，同时保持内嵌图标、关键字、角标避让和原生尺寸渲染行为一致。

## 项目元数据与界面

- 项目根目录新增 `project.yaml`，仅保存可选 `id` 三位数字字符串；旧项目无该文件时视为未设置。
- 新建项目对话框增加可留空的“项目 ID（3 位）”。项目列表 API 保持现有名称列表，另提供项目元数据读取/保存路径，避免无关调用方改动。
- 点击项目（包括当前项目）进入“已选项目、未选卡牌”的状态，右栏显示项目 ID 输入框和保存按钮；新建卡牌等现有流程仍在创建后选中新卡。
- 项目 ID 手动填写须为三位数字，且在本地所有项目中唯一；重命名项目不改变项目 ID。
- 项目 ID 留空时，首次自动编号从 `051` 到 `999` 取全库最小空号并写回元数据。
- 修改项目 ID 只影响之后的自动编号，不改写已有式神/卡牌 ID、文件名或卡图引用。

## 自动编号规则

编号由 store 层统一分配，保存与上传共用；前端不自行决定最终 ID。仅空白 ID 触发自动分配，已有手动 ID 原样保留。

| 条目 | 全长 ID 规则 | 序号方向与范围 |
| --- | --- | --- |
| 主要式神 | `1<项目ID><两位序号>`（首位异画位自动取 `1`） | `01` 起递增 |
| 普通所属卡 | `<所属式神六位ID><两位序号>` | `01–20`，取最小空号 |
| 协战牌 | `<两位所属式神中较小的六位ID><两位序号>` | `21–50`，取最小空号 |
| 衍生卡 | `<所属式神六位ID><两位序号>` | 共用 `51–99`，从 `51` 递增取空号 |
| 衍生物式神 | `<所属式神六位ID><两位序号>` | 共用 `51–99`，从 `99` 递减取空号 |
| 中立牌 | 八位独立 ID | `19999999` 起在全库递减 |

- 非式神、非协战卡新增可选布尔 `token`，GUI 显示“衍生牌”勾选框；它只标记衍生属性和选择 `51+` 号段，不自动删除稀有度或改变其他字段。
- 衍生物式神仍按“类型为式神且有 `shikigami`”识别，不使用 `token`。
- 衍生卡与衍生物式神共用 `51–99`，从两端向中间分配并跳过完整 ID 占用，不设严格编号分界；两者耗尽同一号段时才报号段耗尽。
- 自动给所属卡编号前，若相关主要式神尚无 ID，先按项目规则补齐；协战两位所属式神都如此。
- 中立规则优先于普通/衍生所属卡规则；协战仍要求两位所属式神。
- 项目 ID 和生成的完整卡牌 ID 均跳过全库已有占用值，避免导出合并时冲突；非法或不可解析的既有 ID 不参与序号极值计算，但完整字符串冲突仍须避开。
- 删除或改号留下的空号可以复用。号段耗尽、所属式神缺失或无法形成合法前缀时明确报错，不静默回退卡名。
- 自动编号后保留现有 YAML 文件 stem 与多版本归组方式；上传的新卡图按最终 ID 命名。已有卡图不因单纯补 ID 而改名。

## 保存、上传与数据一致性

- `save_card` 在 schema 初验后、落盘前执行自动编号；新建卡牌的首次保存也会直接获得 ID。
- 上传接口编号时使用当前表单的类型、所属式神和 `token`，不能只依赖已保存旧数据；返回最终 `id` 与图片路径。
- 保存响应同样返回最终 `id`。前端仅在响应仍属于当前选择和当前编辑 revision 时同步表单及已保存快照，防止慢响应覆盖后续编辑。
- 上传分配的 ID 与卡图写入沿用现有串行写锁、异常回滚和选择序号防护；自动补写的项目/所属式神元数据由后端统一处理。
- 原“ID 未填写将回退按卡名命名”提示移除；版本日期留空取当天及其他保存校验提示保留。
- 无 ID 旧数据的卡名重命名/卡图复制逻辑继续服务尚未触发自动编号的路径，不做无关迁移。

## 标点避让

在 `render/text.py` 的贪心换行器内增加“禁止行首标点”约束，不做排完后的二次移动。

- 仅约束自动换行；显式 `\n` 后由用户主动放在行首的标点原样保留。
- 初始集合覆盖中文句读和闭合标点、常见英文句读和闭合标点：`，。！？；：、,.!?;:%）】》〉」』〕〗〙﹚﹜﹞”’)]}`，以及连续省略号中的 `…`。
- 当追加标点会超宽时，将当前行末尾的一个可见文字或图标、已有连续闭合标点及新标点一起移到下一行。例如“测试。”需要换行时移动“试。”，而不是把“。”留在新行。
- 图标是一个可见排版项；移动图标与标点时，同行文字—图标间距重新计算，行首/行尾不多留空格。
- 每次移动后重新执行行宽、逐行居中、掩膜角标避让和区域高度检查；排不下时沿用现有居中点上移与字号递减。
- 极窄行无法同时满足“非空上一行”和“禁止行首标点”时允许排版失败并尝试更小字号；最小字号仍无法满足则沿用现有兜底，优先保证内容可渲染。
- 卡牌描述与共用此排版器的机制正文统一生效；卡名、脚注等不换行文本不变。不额外实现“禁止行尾前引号”等未要求的规则。

## 测试与验收

- store/API：项目 ID 校验、唯一性、自动从 `051` 补号、改项目 ID 不迁移旧卡。
- 各号段首张、空号复用、递减衍生物、协战较小前缀、所属式神自动补号、号段耗尽及全库冲突跳过。
- `token` schema 白名单与 GUI 显隐；中立牌从 `19999999` 递减。
- 保存和上传返回并同步自动 ID，上传使用未保存的衍生/所属信息，旧响应不得覆盖新选择。
- 文本：普通/连续标点、文字和图标携标点下移、显式换行例外、角标窄行、字号与原生尺寸缩放。
- 最终运行全量 pytest、前端 Node 语法与行为测试，并以实际 GUI 验证项目编辑、保存/上传和预览。

## BWPro 配套事项

BWPDIY 的中立牌规则定为 `19999999` 起递减（首位为异画位）。后续另在 BWPro 同步中立 ID 校验、默认示例与相关测试；该项不属于本设计文档的 BWPDIY 代码实施范围。
