# v1.8.3 卡牌描述语义排版设计

## 目标

在不修改用户原始输入、存档 YAML 或布局配置的前提下，优化式神/卡牌描述：

1. 开头的卡牌自身关键字与类关键字能力独立为首行，隐藏该行末尾句号。
2. `条件：`、`增强：`、`响应：`、`觉醒：` 前可自动断行，但只有整体效果更好时才采用。
3. 保持大字号、少行数、逐行居中、行首标点避让、内嵌图标和角标避让的既有优先级与行为。

机制描述框不启用本轮语义排版。

## 三态排版模式

卡牌新增可选字段 `text_layout`，枚举为 `smart` / `wrap` / `off`，缺省与 BWPro 等外部渲染调用均按 `smart`：

- **智能（smart）**：启用本轮关键字首行、条件类候选断行，以及既有自动换行、字号适配、标点避让和角标避让。
- **仅换行（wrap）**：沿用本轮之前的自动换行与完整适配逻辑，不启用关键字首行和条件类候选断行。
- **关闭（off）**：只按用户显式 `\n` 分行，使用文本区最大字号；不自动换行、不缩小字号、不做语义断行或角标避让。逐行水平居中与文本块竖直居中仍保留，超宽/超高内容由用户自行调整。

卡牌库右栏在描述输入框上方提供「自动排版」单选框，选项为「智能 / 仅换行 / 关闭」，仅在「扩展功能」开启时显示。隐藏控件不回退或清除已保存值。机制不提供此字段或控件。

## 首行关键字短句

只识别原文第一个以中文句号 `。` 结束的短句，且短句必须完整位于描述开头；不在正文中搜索、抽取或移动关键字。识别时忽略 `[[...]]` 高亮标记，但不允许图标、换行或其他效果文本混入。

短句按逗号/顿号拆成能力项，每项须命中集中维护的白名单。初版覆盖：

- 通用战斗能力：贯通、连击、吸血、暴击、不屈、远程、直击、先攻、追猎、必杀、屏障、帷幕、迅捷、昂扬。
- 使用与状态能力：瞬发、唯一、不消耗鬼火、气绝时可用、仅气绝时可用。

`突袭`、`坚守`、`鼓舞`、`爆能`、`运势` 等带有后续效果的能力不进入独立首行识别；即使写成独立首句也保持普通排版。

识别成功后，在该短句后插入仅供本次渲染使用的强制断行，并删去短句末尾的 `。`。逗号、顿号、高亮及原始存档均不改写。未完整匹配的短句原样排版，例如 `觉醒：`、带有后续效果的句子不会被抽成关键字首行。

## 条件类候选断行

在解析后的可见文本中查找 `条件：`、`增强：`、`响应：`、`觉醒：`，兼容这些文字被 `[[...]]` 包裹的情况。每个位于段落内部的标签都是一个可选断点；段首标签无需重复断行。

对每个可选断点分别尝试换行/不换行，形成候选排版。为避免异常长输入造成组合爆炸，最多处理前 4 个有效断点（至多 16 个候选），后续标签保持普通文本流。

自动断行不同于用户显式 `\n`：若断行前的最后一个自动排版行宽度不足该行可用宽度的 35%，此候选在当前字号/居中点位置下判为不采用，避免为了语义断行留下过短上一行。该判定使用实际字体宽度并计入内嵌图标，而非简单字符数。

## 比较与适配次序

沿用现有从最大字号到最小字号、每个字号先逐像素上移居中点（至多半行高）的外层顺序。在同一字号和上移量下：

1. 仅保留能完整排下且每行均水平居中的候选。
2. 行数更少者优先。
3. 行数相同时，比较行宽均衡程度，避免出现过短行或明显参差；关键字首行是刻意独立的短行，不参与均衡惩罚。
4. 仍相同时，采用语义断行更完整的候选；再相同则保持原始文本流。

只有当前字号和上移量的全部候选均失败，才继续增加上移量或降低字号。原有闭合/句读标点避让仍作用于每个候选，显式换行后的用户行首标点保持原样。

## 代码边界

- `render/text.py`：集中维护三态模式、首行白名单、语义候选生成、自动断点与候选排序；通用排版缺省保持原行为，卡牌显式传入模式。
- `render/pipeline.py`：仅大卡描述传入 `text_layout`；机制继续调用原路径。
- `store/schema.py` 与卡牌表单：增加可选 `text_layout` 枚举及扩展功能控件；旧数据缺省为 `smart`。
- 不新增布局项或第三方依赖。

## 验证

重点增加定向测试：

- 关键字短句独立首行且仅隐藏末尾句号；高亮与多关键字可用，带后续效果的能力明确排除。
- 普通首句、正文中的关键字、未完整匹配短句不会被重排。
- 条件类标签兼容高亮；候选比较保持最大字号与最少行数，拒绝过短上一行。
- `smart` 缺省生效，`wrap` 回到旧排版，`off` 仅显式分行且不自动缩字号；非法模式被 schema 拒绝。
- 显式换行、标点避让、图标、角标和机制正文回归不变。
- 原始描述与保存数据不被语义排版修改。
