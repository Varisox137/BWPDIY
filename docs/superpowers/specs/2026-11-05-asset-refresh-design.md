# 美术资源更新与对局特殊状态设计

日期：2026-11-05
状态：已获设计批准，待用户审阅书面 spec

## 背景与目标

本批素材同时更新了稀有度、勾玉、内嵌图标、数字与机制角标，并删除了一批旧命名文件。目标是接入新素材而不破坏现有卡图管线、布局坐标、原生尺寸渲染和 BWPro 调用契约，同时补充逐条目内嵌派系样式与大卡特殊状态预览。

采用渐进适配：保留现有渲染架构，只扩展资源加载、数字绘制和必要的元素类型，不重写组件系统，不通过复制素材维持旧路径。

## 已确认的素材口径

- 普通与墨染牌框使用更新后的 `rarity/{N,R,SR,SSR}.png`。协战不再引用已删除的 `reinforce_{R,SR,SSR}.png`，同样回退基础版；琉璃、百炼专版保持 `{R,SR,SSR}_{blue,red}.png` 不变。稀有度仍按可见 alpha bbox 等比缩放到布局尺寸。
- `assets/badges/` 统一存放 `badge_bless.png`、`badge_eclipse.png`、`badge_shown.png`。机制框的左上角仍只使用加护/蚀印；已展示只用于大卡特殊状态。
- `icons/faction_<color>_<1/2/3>.png` 替代旧内嵌派系图及 `_black` 变体；`icons/bounty.png` 补齐描述内嵌 `#sj` 赏金图标，但赏金大角标仍不在本批实现。
- 对局小卡的战力/乏力继续使用 `icons/combat_power.png` 与 `icons/weak.png`，它们是专门绘制的内嵌小图标版本；`stats/combat_power.png` 与 `stats/weak.png` 大图标仅保留备用，不缩小用于对局小卡。其他更新后的 stats/icons/levels/mech 素材继续按现有可见尺寸规则缩放。
- 勾玉颜色新增 `greyblue`（灰蓝）与 `orange`（橙），仅使用现有 1–3 级素材。`level_4_*` 与 `level_3_4_*` 全部保留备用，不开放 4 级，也不替换 3 级引用。

## 位图数字与符号

`assets/numbers/` 提供 white/red/green/purple/orange 五色的 0–9，以及部分正负号和 `white_inf`。内部颜色契约保持 `white/red/green/purple/yellow` 不变，仅把 `yellow` 映射到 `orange` 文件，避免影响 BWPro 与已保存卡牌。

- 大卡和小卡的数字都改用位图素材，不再用田氏颜体逐字绘制并施加程序渐变。
- 以素材 64px 画布高度映射布局 `font_size`，随后按 alpha bbox 裁紧；多位数字仍按相邻字形的逐行墨迹最小水平距离拼接，保留 `_DIGIT_GAP` 与原生尺寸缩放逻辑，数字中点保持水平对齐。
- 正负号同样使用位图。`sign_size_*` 继续表示可见符号尺寸；`num_offset/group_offset/sign_offset` 等布局口径不变。
- 旧 `stroke_width` 配置可以继续存在于 JSON/YAML 中，但不再影响位图数字。GUI 删除数字描边编辑项，文档明确其为无效遗留键；其他布局字段不迁移。
- `white_inf` 替代程序绘制的永久气绝 ∞，按 defeated 的字号规则缩放。
- `orange_minus`、`purple_plus`、`purple_minus` 缺失，使用白色符号轮廓并参考对应颜色数字的渐变各生成一枚正式 PNG 入库。紫色符号只作备用，不改变“紫色主要用于中毒生命”的现有语义。
- 所有数值仍执行最多 10 位限制。资源缺失、未知颜色或非法数值继续明确抛出 `ValueError`/`FileNotFoundError`，不静默回退字体。

## 逐条目内嵌派系样式

卡牌与机制新增可选整数 `inline_faction_style`（1/2/3，缺省 1），分别写入各自 YAML。标记扩展开启时，卡牌与机制右栏显示“内嵌派系样式”下拉；关闭只隐藏控件，不回退已保存值。

描述文本中的所有 `#hl/#cy/#ql/#zy` 派系图标使用本条目的样式。非派系小图标不受影响，墨染框不再自动寻找 `_black` 文件。store、前端校验、渲染文本管线、机制渲染与集成文档同步该字段。

## 大卡特殊状态

对局预览的大卡新增临时 `status`：`None`、`bless`、`eclipse`、`shown` 四态，GUI 显示无/加护/蚀印/已展示，单选其一，不写入卡牌、不置脏，导出与当前预览一致。

六卡牌类型新增 `kind=status` 布局元素：

- 与爆能一样，以等级元素的 `pos` 为锚点，使用自己的 `offset` 和 `icon_size`；默认位于等级组件上方。
- 无等级卡仍按等级布局锚点绘制。
- 全局布局、单卡布局、框品独立布局、拖拽和原生尺寸缩放均沿用现有元素机制；旧布局加载时从包内默认补入。
- 绘制顺序与爆能等框上叠加元素一致，不参与数字避让，不进入 store schema。

## 实施顺序与验证

1. 先补资源加载、路径映射和失败测试，再接入稀有度、派系、勾玉与大角标。
2. 以失败测试固定位图数字的尺寸、颜色、间距、符号和原生缩放，再替换数字实现并生成三枚缺失符号。
3. 增加逐条目派系样式及前后端校验，随后实现 `status` 元素和对局预览控件。
4. 更新术语表、主设计、集成文档、资源清单和使用说明，删除旧引用与失效测试。
5. 运行真实 Web API 渲染、全量 pytest、全部 JS `node --check`、`git diff --check`，并抽查四类牌框、五色带符号多位数字、机制框和三种特殊状态的实际 PNG。

## 明确不做

- 不开放等级 4，不引用 `level_3_4`。
- 不实现赏金大角标，不让已展示成为机制 seal 角标选项。
- 不保留旧 `_black`、旧 signs 或 reinforce 稀有度的兼容副本。
- 不重构其他稳定渲染组件，不改变 BWPro 已有颜色名称和布局坐标系。
