# BWPro 集成审查优化设计

## 背景

`docs/integration-bwpro-review.md` 确认 BWPDIY 的四个渲染入口能够支撑现有集成，问题集中在 BWPro 适配层的资源根推导、异常诊断、预热成功判定和参数遗漏，以及集成文档对部署与缓存边界的说明。本批次同时修改 BWPro 与 BWPDIY 文档，不改变 BWPDIY 渲染 API。

## 方案

采用最小兼容修复：保留现有渲染函数和 `prewarm_all()` 返回类型，在适配层内部补齐诊断、缓存身份与成功清单语义。不引入结构化渲染结果，不调整无关 GUI 结构。

## BWPro 修改

### 资源与参数

- `BWP_DIY_ROOT` 始终优先；缺省时从 `portrait.py` 的各级祖先目录寻找同级 `BWPDIY/assets`，使主检出和 `.worktrees/<分支>` 使用同一资源根。找不到时保留原默认路径作为最终回退。
- 大卡配置中的 `frame_variant` 同时进入渲染负载和 `get_type_layout` 的框品参数；小卡沿用同一负载字段以选择正确的框内卡图窗口。
- 机制 `badge` 进入 `_mechanism_pixmap` 的身份键和 `render_mechanism` 负载。
- 头像 LRU 以图片内容 SHA-256 替代 mtime/大小，覆盖同路径、同大小且保留时间戳的图片替换。

### 异常诊断

- 大卡、小卡、头像、机制和配置解析异常记录渲染类型、卡牌/式神标识或配置路径、资源根及异常堆栈。
- 使用有界去重避免同一失败在界面刷新时反复写日志；清理卡图缓存时同步清除去重状态。
- 占位图仍是 BWPro 的显示策略，不作为渲染成功结果。

### 预热与设置页

- `prewarm_all(library_dir=, cache_dir=)` 将两个显式路径传入大卡和小卡调用。
- 每次预热先构造全部期望条目。只有所需的大卡及小卡均返回非空 `QPixmap`，对应条目才写入成功 `entries`；失败条目写入 `failures` 并保留类型、id、版本和原因。
- manifest 增加 `stats`，记录本次 `succeeded/failed/skipped`。全部期望条目已匹配时跳过渲染并记录跳过数；存在失败时成功清单与期望清单不同，下次启动自动重试。
- `prewarm_all()` 仍返回全部期望条目，避免改变调用方契约。
- 设置页显示缓存条目数、本次成功/失败/跳过统计与失败摘要；完整失败原因保存在 manifest，界面提供其路径。

## BWPDIY 文档

更新 `docs/integration.md`：

- 区分 editable Python 包集成与源码树集成，明确 editable 安装只解决导入，不解决 `assets/` 路径；worktree、非同级目录和便携部署显式配置 `BWP_DIY_ROOT`。
- 区分 BWPDIY 资源缓存、BWPro 图片缓存与预热 manifest，说明内容摘要、配置指纹和失败重试各自由哪层负责。
- 增加调用方失败处理清单：记录上下文与堆栈、占位图不计成功、失败可重试、尺寸在边界校验为正整数。
- 增加大卡、小卡、头像、机制框的最小无 WebGUI 自检，以及非法尺寸应产生可定位异常的检查。

## 测试与验收

- 先添加回归测试并确认旧实现失败，再分别修复：worktree 资源根、异常日志及去重、预热路径转发、失败不写成功清单且下次重试、设置页统计、框品、badge、头像同元数据内容替换。
- 运行 BWPro 相关 GUI 测试和全量 `pytest`；运行 BWPDIY 全量 `pytest`。
- 使用真实 BWPDIY 资源执行四类渲染自检，并验证非法尺寸在调用方日志中可定位。
- 两仓库分别提交并推送；不打包、不发布 Release。

## 边界

- 不修改 BWPro 未提交的 `card_data_raw.md` 与 `library/` 用户内容。
- 不修改 `legacy/`、卡牌规则数据、渲染布局或 BWPDIY API。
- 不引入新依赖，不做与本报告无关的重构。
